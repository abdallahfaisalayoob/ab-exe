(c) Which predictor is better and why?
The 2-bit predictor performs significantly better (9 vs 13 mispredictions). Because it requires two consecutive wrong predictions before switching its prediction, it stabilizes after iteration 1 and correctly predicts all three T outcomes per cycle. The 1-bit predictor flips on every single branch, so it mispredicts almost constantly on this alternating T/NT pattern.
Q2 RISC-V 5-stage pipeline exception handling
(a) Which instructions are flushed?
When add x1, x2, x1 at 0x48 is in the EX stage and the malfunction is detected, the pipeline state is:
StageInstructionAction
EXadd x1, x2, x1 (0x48)Faulting — triggers exception
IDlw x15, 0(x6) (0x4C)Flushed
IFor x13, x2, x6 (0x50)Flushed
Instructions at 0x4C and 0x50 are flushed because they entered the pipeline after the faulting instruction and have not yet committed any state. Flushing prevents them from completing with invalid data. The processor then jumps to the exception handler.
(b) SEPC and SCAUSE registers
RegisterValue storedPurpose
SEPC0x48 (PC of add)Saves the address of the instruction that caused the exception. Used to resume or retry execution after the handler completes.
SCAUSEException code for hardware faultIdentifies the type and cause of the exception so the handler knows how to respond (e.g., retry, report error, or terminate).
(c) Which instruction resumes after the handler?
Execution resumes at address 0x48 (the add instruction), because SEPC holds the PC of the faulting instruction itself. The SRET instruction restores the PC from SEPC, re-fetching and re-executing add x1, x2, x1. This allows the processor to retry the instruction assuming the hardware issue was transient or has been resolved by the handler.

(d) Phenomenon causing repeated misses — Cache Thrashing (Conflict Misses)
The phenomenon is called cache thrashing (or ping-ponging), a type of conflict miss. In a direct-mapped cache, every memory address maps to exactly one cache line determined solely by its index bits. Addresses 4 and 132 both map to index 1 (with different tags), and addresses 68 and 196 both map to index 17. Whenever one address is loaded, it evicts the other. Since the access pattern alternates between the two conflicting addresses, every access finds the needed block missing — it was just evicted by the previous access. This would not occur in a 2-way set-associative cache, where both blocks could reside in the same set simultaneously.
